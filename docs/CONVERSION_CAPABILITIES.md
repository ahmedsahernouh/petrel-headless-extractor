# Conversion capability matrix — 2026-09-14

**Scope correction (2026-09-14):** this broad research is background, not the implementation roadmap. The project targets Petrel binary payload recovery. CSV-to-LAS and other open-format reformatting are excluded from new core features. See [the corrected purpose and priorities](BINARY_EXTRACTION_PURPOSE.md).

[Website](https://saherlabs.dev/) · [Project repository](https://github.com/ahmedsahernouh/petrel-headless-extractor)

**Historical release audited: v0.2.5. ZGY-to-SEG-Y was not available in its BAT.** The table preserves that research snapshot. Version 0.3.0 now includes the [beta ZGY-to-SEG-Y converter](ZGY_TO_SEGY.md); use its documented profile for current applicability.

Version 0.4.0 also adds [native well-log LAS/CSV and surface XYZ/CSV recovery](NATIVE_LOGS_SURFACES.md) to project extraction. That profile supersedes the historical native-log/surface availability entries below for its explicitly supported layouts.

This table separates the installed user feature from development tools and upstream feasibility. An upstream library or installed dependency does not establish application support. Priorities are recommendations: P0 correctness, P1 next practical additions, P2 follow-on work, P3 specialist work, P4 unverified or lower relevance.

Read the [detailed applicability review](CONVERSION_REVIEW_2026-09-14.md) for tests, packaging, metadata requirements and the implementation sequence. [Machine-readable matrix](conversion_capabilities.json) · [Source inventory](conversion_sources.json).

| C01 | ZGY seismic cube | SEG-Y | Prototype tested | P1 | pyzgy/OpenZGY + segyio (bundled). | C02 | ZGY seismic cube | NPY slices/full array + geometry JSON | Development only | P2 | Development MCP ZGY exporter. Existing full-volume path stacks all inlines in memory; replace for large volumes; sidecar must fully define axes. [S01](https://github.com/equinor/pyzgy) |
| C03 | SEG-Y | Header/navigation CSV + text/JSON headers | Upstream documented | P1 | segyio (bundled). Header bytes, coordinate scalar, trace count, units and geometry interpretation must be explicit. [S02](https://segyio.readthedocs.io/en/stable/segyio.html) |
| C04 | SEG-Y seismic cube | NetCDF/Zarr/NPY + metadata | Adapter needed | P2 | segyio + Xarray/backend. | C05 | VDS seismic volume | SEG-Y | Upstream conditional | P3 | OpenVDS SEGYExport. | C06 | SGZ seismic volume | SEG-Y | Upstream documented | P3 | seismic-zfp. Preserve available headers; prior lossy compression is irreversible; avoid SGZ intermediate for direct ZGY export. [S05](https://github.com/equinor/seismic-zfp/blob/master/README.md) |
| C07 | Seismic Unix SU / supported SEG-2 | SEG-Y | Adapter needed | P3 | ObsPy or segyio SU reader. Generate missing file headers and map acquisition metadata; SEG-2 revision-specific; no SEG-D claim. [S24](https://docs.obspy.org/packages/obspy.io.segy.html) [S25](https://github.com/obspy/obspy/blob/master/obspy/io/seg2/seg2.py) |
| C08 | SEG-D acquisition records | SEG-Y | Unverified | P4 | No selected validated adapter. Needs supported revision/vendor records, channel sets, geometry, sample scaling and field datasets; do not advertise. [S03](https://seg.org/wp-content/uploads/2025/11/seg_y_rev2_1-oct2023.pdf) |
| C09 | Well-log LAS 1.2/2.0 | CSV + curve metadata | BAT | Maintain | lasio. Current CSV uses eight significant digits; preserve source LAS, nulls and units. LAS 3 and LiDAR LAS are not equivalent. [S06](https://lasio.readthedocs.io/en/latest/writing.html) [S07](https://www.usgs.gov/programs/national-geological-and-geophysical-data-preservation-program/las-format) |
| C10 | Schema-mapped CSV/Excel well curves | LAS 2.0 | Historical prototype only | Out of scope | Not an implementation priority: both input and output are already open formats. [S06](https://lasio.readthedocs.io/en/latest/writing.html) [S08](https://www.cwls.org/wp-content/uploads/2014/09/LAS_20_Update_Jan2014.pdf) |
| C11 | DLIS scalar log channels | LAS 2.0 / CSV + metadata JSON | Adapter needed | P2 | dlisio + lasio. Separate logical files, frames, index types, duplicate mnemonics and sample rates; retain provenance. [S09](https://dlisio.readthedocs.io/en/latest/dlis/curves.html) [S06](https://lasio.readthedocs.io/en/latest/writing.html) |
| C12 | DLIS image/array channels | HDF5/NetCDF/Zarr + channel metadata | Adapter needed | P2 | dlisio + array backend. Preserve per-sample array axes; flattening to ordinary LAS/CSV is not lossless. [S09](https://dlisio.readthedocs.io/en/latest/dlis/curves.html) [S22](https://docs.xarray.dev/en/stable/user-guide/io.html) |
| C13 | LIS 79 scalar logs | LAS 2.0 / CSV | Adapter needed | P2 | dlisio + lasio. Separate sampling groups and indexes; explicitly handle irregular depth and absent channels. [S10](https://dlisio.readthedocs.io/en/latest/lis/userguide.html) [S06](https://lasio.readthedocs.io/en/latest/writing.html) |
| C14 | WITSML logs/trajectories/tops; PRODML time series | CSV / LAS where suitable + object JSON | Adapter needed | P3 | Version-specific Energistics schema adapter. Standard availability is not a bundled reader; preserve object relationships, units, dates and references. [S18](https://energistics.org/witsml-developers-users) |
| C15 | XLSX/XLSM sheets | Per-sheet CSV | BAT | Maintain | openpyxl (bundled). Reads cached values; does not evaluate formulas or preserve workbook formatting/macros; old XLS unsupported.  |
| C16 | Petrel Well Tops ASCII and validated native spatial layouts | CSV | BAT: subset | Maintain | Existing companion/native decoders. Only explicit supported layouts; native tops require independent ASCII calibration; not every Petrel object/version.  |
| C17 | ZMAP+ regular grid / regular XYZ table | XYZ CSV / ZMAP+ ASCII | Development only | P1 | Development grid converter; zmapio / GDAL. Existing development writer rounds values; inverse requires complete axis-aligned lattice. Harden precision/null/order tests. [S12](https://gdal.org/en/stable/drivers/raster/zmap.html) |
| C18 | IRAP/RMS ASCII or binary surface | XYZ/IJXYZ CSV / GeoTIFF | Adapter needed | P2 | XTGeo + explicit XYZ/raster writer. Preserve rotation, grid origin, node/cell convention, null mask, domain and units; no silent derotation. [S11](https://xtgeo.readthedocs.io/en/latest/datamodels.html) [S15](https://gdal.org/en/stable/drivers/raster/gtiff.html) |
| C19 | Surfer ASCII/binary grid | XYZ CSV / GeoTIFF | Upstream documented | P2 | GDAL GSAG/GSBG drivers. Detect specific format signature; retain nodata, georeferencing and numeric precision; bundled Windows GDAL unresolved. [S13](https://gdal.org/en/stable/drivers/raster/gsag.html) [S14](https://gdal.org/en/stable/drivers/raster/gsbg.html) [S15](https://gdal.org/en/stable/drivers/raster/gtiff.html) |
| C20 | Shapefile | CSV + source-coordinate geometry JSON | BAT: limited | P0 | pyshp (bundled). Current .geojson output is not reprojected: projected coordinates do not satisfy RFC 7946. Document and fix CRS handling. [S16](https://www.rfc-editor.org/info/rfc7946/) |
| C21 | Shapefile / mapped point-line-polygon tables | GeoPackage / WGS84 GeoJSON | Adapter needed | P1 | GDAL + CRS transform. Require verified source CRS for reprojection; retain parts, holes, feature IDs and Z/M semantics. [S16](https://www.rfc-editor.org/info/rfc7946/) [S17](https://gdal.org/en/stable/drivers/vector/gpkg.html) |
| C22 | GOCAD TSurf fault/horizon mesh | VTP/VTK; optional OBJ; vertices+faces CSV | Upstream documented | P2 | GemGIS + PyVista. Preserve topology and properties, ATOM/TFACE variants, coordinate and vertical conventions; XYZ alone drops connectivity. [S20](https://gemgis.readthedocs.io/en/stable/getting_started/reference/raster_api/gemgis.raster.read_ts.html) [S21](https://docs.pyvista.org/api/core/_autosummary/pyvista.polydata.save) |
| C23 | EGRID / GRDECL / ROFF grid and properties | GRDECL / property CSV; optional VTK adapter | Upstream documented | P3 | XTGeo; explicit topology adapter for VTK. CSV cell centers lose corner geometry. Preserve ACTNUM, faults, property coding, IJK order and timestep; no generic GRID support. [S11](https://xtgeo.readthedocs.io/en/latest/datamodels.html) |
| C24 | RESQML EPC + linked HDF5 | Object/property tables; model-aware open derivatives | Adapter needed | P3 | resqpy with schema-specific mapping. Resolve all HDF5 references; preserve UUIDs, topology and CRS. RESQML 2.2 standard does not prove resqpy 2.2 support. [S19](https://resqpy.readthedocs.io/en/latest/_autosummary/resqpy.model.Model.html) [S18](https://energistics.org/witsml-developers-users) |
| C25 | Known HDF5 / NetCDF / Zarr schema | NetCDF/Zarr / selected CSV arrays | Adapter needed | P2 | Xarray / h5py with domain adapter. A container signature does not specify dimensions or meaning; preserve coordinates, units, masks and calendar. [S22](https://docs.xarray.dev/en/stable/user-guide/io.html) |
| C26 | LiDAR LAS/LAZ point cloud | XYZ/attribute CSV or point-cloud derivative | Upstream documented | P4 | laspy / LAZ backend. Detect LASF binary signature; distinct from well-log LAS; preserve scale/offset, CRS, return/classification attributes. [S23](https://laspy.readthedocs.io/en/latest/examples.html) |
| C27 | Unknown native Petrel fault/grid/log/property stores | Universal model export | Unsupported | P4 | No generally validated decoder. Inventory/preserve originals; require object/version-specific parser evidence or a separately authorized application export.  |
| C28 | Generic ASCII/DAT/CSV tables | Typed CSV/XYZ tables | Adapter needed | P1 | Explicit schema mapping and parser. ASCII is an encoding family, not a geological schema. Detect delimiter/encoding/nulls and map IDs, units, CRS and columns.  |
