Field Viewer Data Extractor | 1.0.0-beta.3

The project mindmap: recover supported Petrel data into open files, reports and metadata for further work. Destination tools are examples, not verified integrations.

Use the Desktop edition for the interface shown below, or the Headless edition for command-line and agent use. Original project stores remain read-only.

Public beta 3 release. Review scope and final QC before use.

1. Open Desktop and choose the project

  1. Extract the entire Desktop ZIP into a short writable folder.
  2. Open FieldViewer_Desktop.bat.
  3. Use Petrel project > Browse to select the exact .pet file with its matching .ptd folder.
  4. Use Output folder > Browse. Choose a folder outside the source project.
  5. Choose Full extraction, then click Run.

2. Extract CRS and datum metadata only

  1. Choose the project and output folder in the same way.
  2. Set Mode to CRS and datum only, then click Run.
  3. A static model is not required. This mode reads PET/Model declarations and skips broad project-size scans.
  4. Stored declarations do not verify coordinates, datum selection or dataset binding.

3. Read the final status and open the report

  1. Wait for the final status above the elapsed timer.
  2. Completed with gaps means review the report for missing or unsupported data.
  3. Choose an available report in Reports, then click its Open button.
  4. Use Folders > Open to inspect this run. A folder containing files does not prove complete recovery.

Modes, results and Headless use

ModePurposeCheck
Full extractionRecover supported native data and companions.Review category coverage, QC, metadata and gaps.
Report onlyInventory, reports and previews.Temporary processing can still occur.
CRS and datum onlyStored PET/Model CRS and datum declarations.No 3D grid needed; no coordinate transformation.
RESCUE (experimental)Grid metadata inventory through the CLI.Public beta3 does not export RESCUE models; metadata inventory only.

Read the result

0: completed within the selected mode. 10: completed with gaps. 2: failed. Review the final receipt, HTML report and QC before importing data elsewhere.

Long companion paths may leave individual files or conversions unavailable; successful peers remain registered. Closing the GUI does not cancel its backend. Reopening observes the recorded session.

CRS-only files

CRS_REPORT.html, CRS_DATUM.json, CRS_EXPORT.json, FILE_MANIFEST.json and EVENTS.jsonl. CRS_DECLARATION.xml is written where supported and unambiguous.

Headless examples

Run from the extracted package folder. The check command installs/checks its bundled runtime. The CRS output directory must be new and outside the source project.

FieldViewer_data_extractor.bat --check -NoPause
FieldViewer_data_extractor.bat -ProjectFile "D:\Projects\Example.pet" -OutputRoot "D:\FV"
.\FieldViewer\runtime\python.exe -B .\FieldViewer\scripts\fieldviewer_crs.py --project "D:\Projects\Example.pet" --output "D:\FV\CRS_example"

Before using an export

Check recovered data, units, CRS and datum evidence. Unsupported or ambiguous metadata remains unknown. RESCUE static-model export is not included in public beta3. Use the CLI inventory-only option for grid metadata. Read RELEASE_NOTES.md and KNOWN_LIMITATIONS.md.
